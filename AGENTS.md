# Project instructions

- Read README.md, HANDOFF.md, TRANSLATION_WORKFLOW.md, latin/SOURCE.md,
  and translation/CONVENTIONS.md before translation or publication work.
- Follow the Windows/Python machine instructions supplied by the user.
- Preserve Lindsay's book/chapter/section references. This is prose; do not
  impose the companion poetry projects' meter or line-for-line rules.
- The edition is now explicitly abridged. Keep full-source acquisition distinct
  from selection completeness. Prefer self-contained sections; interesting
  fragments need visible gaps and no speculative completion.
- Keep paired Latin forms visible when an etymology depends on Latin sound
  or spelling. Do not invent an English derivation to replace the Latin one.
- Never invent source text, coverage counts, completed reviews, citations,
  model identities, or acceptance decisions. Unstarted is a valid state.
- Track coverage and accepted text through segments/manifest.json. Keep raw
  downloads separate from corrected working Latin and record corrections.
- Original project contributions use CC0, including notes and code. Do not
  import the companion projects' CC BY material without a rights record.
- No automatic model dispatch or paid API jobs are configured. Record the
  actual contributor/model and review evidence when work takes place.
- The user authorized lower-reasoning subagents. Use fixed, hashed passage
  inputs and narrow output contracts; deterministic scripts validate structure.
  Lead review decides fidelity; user approval settles voice and design.
- Keep the domain configurable. No registration, paid order, Lulu upload,
  or website deployment is part of the initial scaffold.
- Use a separate print build with visual PDF inspection and a physical proof
  before release. Never label manuscript Markdown or an unchecked PDF print-ready.
- Run `python tools/project.py check` after source, translation, or manifest
  edits; run the unit tests after tool changes. Update HANDOFF.md at handoff.
